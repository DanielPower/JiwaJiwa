# core/AGENTS.md

Pure-Kotlin study logic. It must stay free of Android imports so it builds
and tests on any JVM (`./gradlew -PcoreOnly=true :core:test`).

## Files

| File | What's in it |
| --- | --- |
| `Fsrs.kt` | A port of FSRS-6 (py-fsrs 6.3.2), with learning steps and fuzz. `FsrsTest` replays `src/test/resources/fsrs_vectors.tsv`, generated by `tools/fsrs/gen_vectors.py`. If you change the scheduler, regenerate the vectors rather than editing them. |
| `Cards.kt` | `Card`, `WordProgress`, `ReviewLog`, and `Reviewer`, which applies an answer (FSRS + mastery + production unlock), a word read in a story (a share of a Right answer's stability gain), introduces a new word, or marks it known. |
| `Mastery.kt` | `MasteryRules`: stability ↔ mastery mapping and the furigana thresholds. |
| `StudyClock.kt` | Study days with a rollover hour, in a time zone. Review cards fall due at the start of a study day. |
| `Session.kt` | `StudySettings`, `Pace` (the soft daily limit and review nudge), `StudyAhead` ("study more"), `DailyLimits`, and `StudySession`, the order cards are shown in during one sitting. |
| `Kana.kt` | Romaji → kana for search, hiragana/katakana variants. |
| `KanaCourse.kt` | The kana as taught: every unit (きゃ and っ are one each) with its Hepburn romaji, splitting text into units, the order the stories need them in, sets of 5 with lookalikes apart (`KanaLooks`). |
| `KanaDrill.kt` | Kana practice outside FSRS: `KanaProgress` and its stages, `KanaState` (what's due, unread, unclear), `KanaSession` (one sitting's multiple-choice questions) and `Distractors`. |
| `Romaji.kt` | Romaji for unread kana (っ and ー by their neighbours), and `romajiPieces`, a word's ruby with romaji over the kana you can't read yet. |
| `Kanji.kt` | `Kanji` entries, the kanji in a word from its furigana, and which dictionary reading a word uses (allowing for rendaku, small っ and verb stems in compounds). |
| `Reading.kt` | What a read story is made of: `ReadingWord` (a word, its dictionary entry, conjugation labels, grammar and furigana), `Morpheme` (a token, which `Grammar.kt` patterns match), paragraphs and `Speech` (who's speaking). The reading itself happens at build time, in `src/stories`. |
| `StoryText.kt` | The stories as the tools read them, a file per story under `stories/read/` (compact JSON, a paragraph a line), which the app parses and shows. |
| `Grammar.kt` | Hand-written grammar points (particles, N5 and N4 patterns, a few N3), each with token patterns over Kuromoji output. `Reader` attaches them to words; a match inside a longer match is dropped. `GrammarTest` checks every point's own example sentence finds it, so add an example that does. A `lesson` point has no pattern (`inText = false`): grammar the reader reads as words, such as counting, which only its topic's lesson explains. A rule can guard the token before (`before`) or after (`after`) its match. `StoryPathTest` fails on any particle, ending or changed form in the stories that no point explains. `LABEL_POINTS` says which points explain each conjugation label, so the reader's word pane can show a label only when none of the word's points covers it (`unexplainedConjugation`). |
| `StoryPath.kt` | The bundled story path: parsing `path.json` (stories of chapters, and grammar topics), the words and grammar each chapter needs, which chapters are within reach, and the solver that proves every chapter can be reached. |
| `src/stories/` | The story tools, not part of the app (their own source set, with Kuromoji and SQLite JDBC). `Reader.kt` groups Kuromoji tokens into words, matches them to the built dictionary (`bestHomograph`), and gives conjugation labels and grammar; a new conjugation label needs a row in `LABEL_POINTS` (`Grammar.kt`). `Tokens.kt` repairs tokens IPADIC misreads in everyday speech, each with a case in `ReaderTrapsTest`. `StorySource.kt` puts `path.json` together from `tools/stories`; `StoryAssetsTool.kt` writes it, `needs.json` and `stories/read/` for the app build (`:core:storyAssets`, not committed); `StoryTools.kt` writes each story's `SUMMARY.md` and `tools/stories/COVERAGE.md` (`./gradlew -PcoreOnly=true :core:stories`, with `-Pchapter=story/slug` for one chapter's report); `StoryCheck.kt` holds the story checks it prints and `StoryPathTest` fails on. |
| `Coverage.kt` | How a story's words measure up against what you know, and a finished read's stats. |
| `VerticalText.kt` | Line breaking for the vertical story reader: which column each run of characters goes in, with Japanese line-break rules (hanging 、。, closing brackets never start a column, opening ones never end one). |
| `HorizontalText.kt` | Line and page breaking for the horizontal story reader, from measured word widths, with the same rules (`Kinsoku.kt` holds the shared character sets). |
| `Sentences.kt` | Splits story paragraphs into sentences (a quote stays with the words around it), which the bundled English follows. |
| `RenshuuImport.kt` | Plans a Renshuu mastery import (take the higher). |

## Things that are easy to get wrong

- Mastery follows the recognition card. Production answers
  must not change it.
- `Direction` and `CardState` values are stored in the app's database. Don't
  renumber them; add new values at the end.
- Value 2 was `Direction.KANA` (kana cards, removed); don't reuse it.
- `LABEL_POINTS` in `Grammar.kt` maps each conjugation label the reader
  (`src/stories/.../Reader.kt`) can give a word ("past", "want to", "completely or regrettably") to the
  grammar points that explain it. When you add a label, add its row; when
  you add a point that explains a label (a new ～て… helper, say), add its
  id to that label's row. A missing row doesn't hide anything, but the pane
  then shows the label next to the link that already says it
  ("～たい want to › · want to").
- Elapsed time for FSRS is counted in study days, not 24-hour periods.
- Times are epoch milliseconds; days are epoch days of the study day's
  calendar date. Tests use `America/St_Johns` (a half-hour offset with DST)
  to catch time zone mistakes.

## Tests

`src/test/kotlin`, JUnit 5 via `kotlin.test`. Name tests as backtick
sentences about behaviour. Anything the app does that doesn't need Android
should be pulled into core and tested here.
